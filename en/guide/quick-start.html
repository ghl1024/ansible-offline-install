Quick Start ​

The route in one line: check your server's OS, architecture and Python version → pick the matching bundle from the table → copy it over and run install.sh → "ping": "pong" means you are done.

Before you start: check your server's info ​

Run these three commands on your server and note the results; you will need them to pick the right bundle:

bash
cat /etc/os-release     # OS: Rocky Linux 9 / Ubuntu 24.04 / Debian 12 ...
uname -m                # CPU architecture: x86_64 or aarch64 (aarch64 = ARM64)
python3 --version       # Python version: 3.11 or newer is required
  • OS is in the supported set: EL 9 family / Ubuntu 24.04 / Ubuntu 22.04 / Debian 12 (see the Platform Matrix)
  • Architecture is either x86_64 or aarch64
  • Python version is >= 3.11

💡 Root is not required. A regular user can install (into their home directory); installing as root makes Ansible available system-wide.

  • The machines Ansible will manage (managed nodes) need nothing special: just SSH and any Python. That is Ansible's own rule, unrelated to this project.

Install in 3 steps (beginner path) ​

Step 1: Download the bundle that matches your server ​

  • Use the table on the Download & Verify page to pick and download your bundle. From inside China, the Gitee mirror is usually faster.

Step 2: Copy the bundle to the offline server and extract it ​

  • Copy the .tar.gz file to the server (USB, bastion host, internal file server), then:
bash
tar xf ansible-offline-install-2.0.0-el9-aarch64-py311.tar.gz
cd ansible-offline-install-2.0.0-bundle

Step 3: Run the installer and check the result ​

bash
bash install.sh
  • The script prints its progress line by line (in Chinese by default; add --lang en for English) and runs a self-check at the end. Output containing "ping": "pong" means success:
[ansible-offline] Verifying installation
localhost | SUCCESS => {
    "changed": false,
    "ping": "pong"
}
[ansible-offline] Done. Ansible is ready, fully offline.

✅ Try ansible --version - if it prints a version, you are ready to write your first playbook.

  • Stuck? Check the FAQ. Want a different Ansible version or a different set of collections? See Build Your Own Bundle.

Glossary (when a term is unclear) ​

  • Offline bundle: one archive file containing everything needed for installation, so it works on machines without internet.
  • wheel: Python's prebuilt package format - like a Windows installer; no compiling at install time, fast and reliable.
  • venv (virtual environment): a dedicated folder holding this Ansible installation, isolated from the system; deleting the folder removes it completely.
  • collection: an Ansible plugin package that adds features, e.g. modules for firewalls or cloud providers. This project bundles ansible.posix and community.general, the two most commonly used ones.
