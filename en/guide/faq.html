FAQ ​

Find your error message first - this page is organised by symptom. If nothing matches, see "Still stuck?" at the end.

ansible says "command not found" after installing? ​

For regular-user installs, commands are linked into ~/.local/bin, which may not be on your PATH yet. Either fix works:

  • Run export PATH="$HOME/.local/bin:$PATH" and try again
  • Or simply open a new terminal

The script says python3 is missing, or Python >= 3.11 is required? ​

Install Python for your OS (this does not disturb anything else):

  • EL 9: sudo dnf install -y python3.11 python3.11-venv (or python3.11-devel if there is no venv subpackage)
  • Ubuntu 22.04 / Debian 12: sudo apt install -y python3.11 python3.11-venv
  • Ubuntu 24.04 ships Python 3.12, so this error should not appear there.

The script says "wheelhouse not found"? ​

⚠️ Almost always this means only install.sh was copied, or the script was run outside the extracted folder.

  • Do this instead: extract the full .tar.gz, change into the ansible-offline-install-2.0.0-bundle folder, then run it. The "wheelhouse" is the folder inside the bundle holding all install files; without it, offline installation is impossible.

Does CentOS 7 work? ​

❌ No. CentOS 7 reached end of life in 2024 and its Python is too old for current Ansible.

  • Please use an EL 9 family system (e.g. Rocky Linux 9). The very first version of this project targeted CentOS 7; it has since been fully rewritten and CentOS 7 is no longer supported.

Will this break my system's Python? ​

✅ No. Everything is installed into a dedicated folder; only the ansible commands are linked out.

  • Locations: /opt/ansible-offline for root installs, ~/ansible-offline for regular users. The system Python and other programs are untouched.

I don't want the bundled collections. ​

  • Run INSTALL_COLLECTIONS=0 bash install.sh to skip them. A collection is an Ansible plugin package; two popular ones are included by default, see Build Your Own Bundle.

Can the scripts print in English / Chinese? ​

Yes, two ways:

  • Command-line flag: bash install.sh --lang en
  • Environment variable: ANSIBLE_OFFLINE_LANG=en

Both scripts speak Chinese by default and support both options.

How do I uninstall? ​

  • Delete the install folder and the command links - nothing is left behind:
bash
# If installed as root:
rm -rf /opt/ansible-offline /usr/local/bin/ansible*
# If installed as a regular user:
rm -rf ~/ansible-offline ~/.local/bin/ansible*

The build machine cannot reach PyPI or Galaxy (no overseas network)? ​

This is exactly why this project keeps mirrors on China-based platforms:

  • You just need Ansible installed: skip building and download a ready-made bundle from the Releases on GitHub or Gitee (Gitee is the China mirror); the bundles already include the collections.
  • You do need to build (e.g. for a different Ansible version): point pip at a domestic mirror by prefixing the build command: PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple bash scripts/make-offline-bundle.sh (Tsinghua mirror shown; Aliyun and others work too).

⚠️ Note: the collections are downloaded from Galaxy overseas and have no stable domestic mirror - if that step cannot connect, use a ready-made bundle instead.

Still stuck? ​

Open an Issue in the primary repository. Including these three things saves a lot of back-and-forth:

  • Your OS version (the output of cat /etc/os-release)
  • The exact bundle file name you used
  • A screenshot or the full text of the error
