常见问题 ​

先按你看到的报错关键词在本页找答案——本页就是按报错场景组织的。找不到，再看文末的「还是没解决？」。

运行 ansible 时提示 command not found？ ​

普通用户安装时命令被链接到 ~/.local/bin，这个目录可能还没加进 PATH。两种解决办法，任选其一：

  • 执行一次 export PATH="$HOME/.local/bin:$PATH" 再试
  • 或者重新打开一个终端窗口

脚本报错「未找到 python3」或「需要 Python >= 3.11」？ ​

按你的系统装一下 Python 即可，不影响其他东西：

  • EL 9：sudo dnf install -y python3.11 python3.11-venv（没有 venv 子包时装 python3.11-devel）
  • Ubuntu 22.04 / Debian 12：sudo apt install -y python3.11 python3.11-venv
  • Ubuntu 24.04 自带 Python 3.12，一般不会报这个错。

脚本报错「未找到 wheelhouse」？ ​

⚠️ 几乎都是因为只拷了 install.sh 一个文件，或者没有在解压出来的文件夹里运行。

  • 正确做法：把完整的 .tar.gz 解压后，进入 ansible-offline-install-2.0.0-bundle 文件夹再运行。wheelhouse 就是包里存放全部安装文件的文件夹，缺了它就没法离线安装。

CentOS 7 能不能用？ ​

❌ 不能。CentOS 7 已在 2024 年停止维护，自带的 Python 版本也太老，新版 Ansible 装不上。

  • 请把系统换成 EL 9 系列（如 Rocky Linux 9）。本项目最早的版本就是给 CentOS 7 做的，后来整体重构，不再支持。

会不会把系统原有的 Python 搞坏？ ​

✅ 不会。Ansible 全部装进独立文件夹，只是把 ansible 等命令做了链接。

  • 具体位置：root 安装在 /opt/ansible-offline，普通用户在 ~/ansible-offline。系统 Python 和其他程序完全不受影响。

包里自带的 collections 我不想装？ ​

  • 运行 INSTALL_COLLECTIONS=0 bash install.sh 即可跳过。collection 是 Ansible 的插件包，默认附带了两个最常用的，见自制离线包。

脚本能显示英文吗？ ​

可以，两种方式：

  • 命令行参数：bash install.sh --lang en
  • 环境变量：ANSIBLE_OFFLINE_LANG=en

安装脚本和打包脚本都支持，默认中文。

怎么卸载？ ​

  • 删掉安装目录和命令链接即可，没有残留：
bash
# root 安装的：
rm -rf /opt/ansible-offline /usr/local/bin/ansible*
# 普通用户安装的：
rm -rf ~/ansible-offline ~/.local/bin/ansible*

我在联网机器上打包时，连不上 PyPI 或 Galaxy 怎么办？ ​

这正是本项目在国内平台设镜像的原因，分两种情况：

  • 只想装 Ansible：别自己打包了，直接去 GitHub 或 Gitee 的 Releases 下载现成离线包（国内网络选 Gitee），现成包里已经包含 collections。
  • 确实要自己打包（比如要换版本）：给 pip 换一个国内源，在打包命令前面加一个环境变量即可：PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple bash scripts/make-offline-bundle.sh（示例是清华源，阿里云等其他国内源也可以）。

⚠️ 但要提醒：collections 是从海外的 Galaxy 下载的，国内没有稳定镜像，这一步连不通时，请用上面下载现成包的办法。

还是没解决？ ​

到主仓库 Issues 里留言，留言时尽量带上这三样，能省去很多来回：

  • 你的系统版本（cat /etc/os-release 的输出）
  • 你用的离线包文件名
  • 报错截图或完整报错文字
